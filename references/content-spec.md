# 内容与图片规范

## 事实来源

品牌为 Shenguan Watch，面向腕表品牌、进口商、经销商、批发商及礼品采购。
产品库限定 `/watch/` 的手表，依据具体型号区分自动机械表、石英表、木表、镶饰腕表等。

产品事实仅限标题、产品简介、技术参数表和产品专属介绍。逐条审查
`facts.declared`、`facts.corroborated`、`facts.variations` 和 `source_sections`。
重复出现不等于独立权威验证；保留限定词和单位。标题不是规格表的替代品。
“Japanese movement or Swiss movement”“mineral glass or sapphire glass”及
“5 ATM, 10 ATM, 20 ATM”等是待确认选项，不能改成默认瑞士机芯、蓝宝石玻璃或固定 20 ATM。
`Customized` 不提供确切尺寸；`Custom Movement: unacceptable` 不能改写为可定制机芯。

摘要、正文与参数表的机芯类型、材质、SKU、尺寸、防水等级和配置必须相容。
真实冲突在提交前拒绝候选。明确用 `or` 连接的材质、玻璃、机芯选项列表，如一处只是
另一处的子集，保留到 `facts.variations`，仅使用共同较窄的原文选项列表并保留“可选”限定。
这不算独立佐证，也不允许推广只在较宽列表中出现的额外选项。互斥描述或默认配置差异不能合并。
ATM 数值按原文表达，不自行换算成下潜深度，也不由商品名推导潜水认证、游泳或水下操作。
“iced out”不能证明天然钻石；镀层不能宣传为实心贵金属；外观不能证明蓝宝石、机芯品牌
或动力储备。木材、环保、可持续来源、抗过敏、耐刮等断言不能凭外观或营销形容词确定。
如产品证据没有可核实依据，省略此类断言或向买家提出需确认的采购问题。
价格、MOQ、交期、产能、认证、保修和产地也必须有该型号的可靠依据。
通用工厂、质检、包装物流、选项卡片、评论、FAQ、图片 alt 不可补足产品事实。

`content-plan.json` 自动提供产品主题和有证据的相关方向，供社媒选题和标签使用。
不要求文章关键词密度、SEO 标题或额外行业文章。外部研究若有必要，记录来源，只作
一般背景，不能替换该产品的官网证据。

## Facebook

80–150 个英文词，依次包含：

1. 四行 emoji 开头的已核实特点。可用 ⌚、🕒、💎、🌳、💧、⚙、📦、✅、💡、📏、🛠、🔧、🏭；图标本身也不得暗示不存在的材质或性能。
2. 一段简短的用途和采购价值，场景须受该产品证据支持。
3. 一句明确询盘 CTA。
4. 独占一行的完整规范产品 URL。
5. 8–12 个不重复且相关的英文标签。

## LinkedIn

150–250 个英文词，依次包含：

1. 专业的腕表选品、品牌配置或采购问题引入。
2. 3–5 条简明参数或功能要点，使用 `-` 或 `•`。
3. 一段已核实用途及买家价值。
4. 经销、批发、OEM/ODM 或贴牌询盘 CTA；具体供应能力需有对应来源。
5. 独占一行的完整规范产品 URL。
6. 3–5 个不重复的英文标签。

两个平台分别撰写，不能完全重复。面向腕表品牌、进口商、经销商、批发商和礼品采购者。
佩戴场景须有产品依据，默认使用中性产品展示。语言专业具体，避免夸张宣传。
校验器按所有英文词计数（包括 URL 和标签中的英文词）；保持总数处于范围中间。

## 四宫格图片

只生成一张正方形图片，四个清晰分隔的区域和干净间距。以下载的真实主图作为参考，
展示同一型号的互补视图：完整腕表、中性佩戴或棚拍、表盘细节、表壳与表带细节。
不明确的应用场景、包装或附件改用中性棚拍视角。不能推断缺失配件或不存在的颜色。
保持表盘布局、指针、刻度、日历窗、表圈、表冠、表耳、表带和可见标识。
不可凭空增加计时小表盘、透底机芯、钻石、附件、礼盒或防水场景；禁止新加标题、
徽章、认证、标志或水印。没有背面参考图时不生成背透或内部机芯视图。

先用 `view_image` 查看主图，再加载 `imagegen`，将主图本地路径传给生成工具。
生成文件必须复制到运行目录后再交付，不把工具缓存作为唯一成品。

### 审核与有界恢复

允许合理灯光、反射、阴影、背景、透视和非功能性纹理差异。不能接受型号、主要结构、
表盘功能、表带结构、清晰文字或品牌出错，也不能表现不受支持的操作。
初次生成后最多两次针对性修正；仍失败时再允许一次保留真实源产品、仅改变背景及布局
的四宫格合成。最多四次生成。失败则保留证据并停止；不换品绕过生成错误。

规范成品 `social.webp`：1:1，建议 1600×1600，最低 960×960，不大于 750 KiB；
压缩质量不低于 68，不放大小图凑尺寸。用像素重建移除 EXIF/XMP/ICC 等源元数据。
上传副本 `social-upload.jpg`：同样正方形、最低 960×960、无元数据、不大于 750 KiB。
Facebook 和 LinkedIn 都上传此 JPEG，以保持浏览器上传兼容性。
双平台都核验成功前保留 JPEG 供安全续跑，之后可删除，规范 WebP 必须保留。

## 发布前审核记录

保存 `evidence/review.json`。如下为结构，填写真实结论和原文证据，不能把占位值当作通过：

```json
{
  "product_url": "实际规范产品URL",
  "source_review": "passed",
  "copy_review": "passed",
  "image_review": "passed",
  "claims": [
    {"claim": "文案特点", "quote": "source_sections 中的精确原文"}
  ],
  "image_attempts": 1,
  "image_versions": [],
  "accepted_minor_differences": [],
  "material_issues": [],
  "sha256": {
    "product_json": "实际SHA256",
    "source_hero": "实际SHA256",
    "facebook_copy": "实际SHA256",
    "linkedin_copy": "实际SHA256",
    "social_image": "实际SHA256",
    "social_upload": "实际SHA256"
  }
}
```

`claims` 至少四项，并覆盖两份文案中的全部技术、功能和供应能力断言。额外保存
`evidence/image-review.json` 记录每次生成路径、检查结论、问题和修正。`sha256` 用
Python `hashlib.sha256(Path(path).read_bytes()).hexdigest()` 计算，检查最终压缩图后填写。
脚本验证格式和证据引用，不替代语义核验或视觉审核。
